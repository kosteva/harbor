### [Infinite Image Browsing](https://github.com/zanllp/infinite-image-browsing)

> Handle: `iib`<br/>
> URL: [http://localhost:35060](http://localhost:35060)

IIB is a fast browser and search UI for images and videos, originally built as an extension for
`sd-webui`/ComfyUI and also runnable standalone. Harbor runs it via
[`PBandDev/infinite-image-browser-docker`](https://github.com/PBandDev/infinite-image-browser-docker),
a third-party Docker packaging of the upstream project that publishes a ready-to-use image.

![IIB screenshot](./harbor-iib.png)

> [!IMPORTANT]
> Only files under `/outputs` inside the container are indexed and therefore searchable. The
> `HARBOR_SWARMUI_OUTPUT` folder is mounted there by default at `/outputs/swarmui`; use
> [`harbor iib paths`](./3.-Harbor-CLI-Reference.md#harbor-iib) to add more directories the same
> way. Do not confuse this with `EXTRA_PATHS`, which the upstream image also supports but only
> for browsing — paths added that way are not indexed or searchable, which is why Harbor's `iib`
> CLI doesn't use it.

> [!NOTE]
> The published image is `linux/amd64` only. `services/compose.iib.yml` pins `platform:
> linux/amd64`, so on Apple Silicon (and other non-amd64 hosts) it runs under emulation. Basic
> browsing and search are fine; video thumbnail/cover generation (which shells out to
> ffmpeg/`av`) is noticeably slower than on native hardware.

#### Starting

```bash
harbor up iib --open
```

#### Configuration

##### Environment Variables

Following options can be set via [`harbor config`](./3.-Harbor-CLI-Reference.md#harbor-config):

```bash
# Web UI port on the host
HARBOR_IIB_HOST_PORT      35060

# Image repository / tag. No official image is published upstream (see the
# upstream README); this is the actively-maintained third-party build.
HARBOR_IIB_IMAGE          ghcr.io/pbanddev/infinite-image-browser-docker
HARBOR_IIB_VERSION        latest

# Persistent index database (iib.db) and thumbnail/video-cover cache
HARBOR_IIB_CACHE          ./services/iib/cache

# Optional passphrase. Once set, the UI and API require it - see below.
HARBOR_IIB_SECRET_KEY     ""

# UI language: en, zh, or auto
HARBOR_IIB_SERVER_LANG    en

# Extra CLI args appended to the entrypoint (maps to EXTRA_OPTIONS), e.g.
# for multiple non-indexed browse-only roots: --extra_paths /outputs /mnt/foo
HARBOR_IIB_ARGS           ""
```

Use the [`harbor iib`](./3.-Harbor-CLI-Reference.md#harbor-iib) CLI to manage the service without
invoking `harbor config` directly:

```bash
harbor iib version [tag]     # Get/set the image docker tag
harbor iib image [image]     # Get/set the image repository
harbor iib args [args]       # Get/set EXTRA_OPTIONS
harbor iib secret [key]      # Get/set IIB_SECRET_KEY
harbor iib cache             # Open the cache folder in the File Manager
```

##### Adding browse/search paths

```bash
harbor iib paths ls                  # List configured paths
harbor iib paths add <dir> [label]   # Mount a host directory read-only under /outputs/<label>
harbor iib paths rm <label|index>    # Remove a configured path
harbor iib paths clear               # Remove all configured paths
harbor restart iib                   # Apply changes - paths are read at container start
```

`label` defaults to the directory's basename, slugified to lowercase letters, numbers, and
hyphens. `swarmui` is reserved for the built-in default mount. For example:

```bash
harbor iib paths add ~/Pictures
harbor iib paths add ./services/comfyui/workspace/ComfyUI/output comfyui
harbor restart iib
```

> [!NOTE]
> Custom paths are implemented via Harbor's generic
> [`harbor volumes`](./3.-Harbor-CLI-Reference.md#harbor-volumes) mechanism (`harbor iib paths` is
> a thin, validating wrapper storing into `HARBOR_IIB_VOLUMES`) and are only injected when
> `legacy.cli` is `false`, which is the default. If you've set `harbor config set legacy.cli true`,
> added paths will not appear in the container.

##### Volumes

- `${HARBOR_SWARMUI_OUTPUT}` → `/outputs/swarmui` (read-only) — mounted by default.
- Paths added via `harbor iib paths add` → `/outputs/<label>` (read-only).
- `${HARBOR_IIB_CACHE}` → `/cache` — index database and thumbnail/video-cover cache.

All image mounts are read-only, so delete/move/copy operations from the IIB UI will fail rather
than modify your files. The container itself runs as root (the upstream image ships no non-root
user), so no ownership-fixup sidecar is needed for `/cache`.

##### Access control

If `HARBOR_IIB_SECRET_KEY` is set, the UI prompts for it and the API rejects unauthenticated
requests (including the `/version` healthcheck endpoint used below). Leave it empty for a
single-user local install.

##### Migrating an existing index

If you already have an `iib.db` from running IIB elsewhere and want to re-point recorded paths at
their new location inside the container:

```bash
docker exec harbor.iib python migrate.py --db_path /cache/iib.db --old_dir "/old/path" --new_dir "/outputs/<label>"
```

#### Integrations

**Reverse proxy / external access**

- With `traefik` present: `compose.x.traefik.iib.yml` adds Traefik labels so the UI is reachable
  at `https://iib.${HARBOR_TRAEFIK_DOMAIN}` (websecure entrypoint, port derived from container
  port 8080).

#### Troubleshooting

##### Check Logs

```bash
docker logs harbor.iib
```

`harbor logs iib` also works but tails by default — prefer `docker logs` for a one-shot look.

##### A newly added path doesn't show up

Confirm it was written and that the service was restarted:

```bash
harbor iib paths ls
harbor restart iib
docker exec harbor.iib ls /outputs
```
