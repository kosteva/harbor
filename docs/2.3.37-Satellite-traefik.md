### [traefik](https://github.com/traefik/traefik)

> Handle: `traefik`<br/>
> URL: [http://localhost:34373](http://localhost:34373)

![traefik screenshot](harbor-traefik.png)

Traefik (pronounced traffic) is a modern HTTP reverse proxy and load balancer that makes deploying microservices easy.

#### Starting

```bash
harbor up traefik
```

- Harbor creates relevant traefik service files [via a seed script](../.scripts/seed-traefik.ts).

#### Configuration

If Harbor's [default traefik config](../services/traefik/traefik.yml) doesn't suit your needs the
expected way to configure traefik is to provide a custom configuration file.

```bash
# Path should either be global or relative to $(harbor home)
harbor config set traefik.config /path/to/your/traefik.yml
```

Apart from that, the following options can be set via [`harbor config`](./3.-Harbor-CLI-Reference.md#harbor-config):

```bash
HARBOR_TRAEFIK_HOST_PORT              80
HARBOR_TRAEFIK_HTTPS_HOST_PORT        443
HARBOR_TRAEFIK_METRICS_HOST_PORT      34372
HARBOR_TRAEFIK_DASHBOARD_HOST_PORT    34373

# Traefik version to use (docker image tag)
HARBOR_TRAEFIK_VERSION                v3
# Docker image to use for traefik
# the default one is from traefik's official docker hub
HARBOR_TRAEFIK_IMAGE                  traefik

# Default Harbor setup will pre-configure services
# on the <service-handle>.${HARBOR_TRAEFIK_DOMAIN} domain
# example: ollama -> ollama.lan
HARBOR_TRAEFIK_DOMAIN                 lan

# Path should either be global or relative to $(harbor home)
HARBOR_TRAEFIK_CONFIG                 ./services/traefik/traefik.yml

# URL that'll open when you call "harbor open traefik"
HARBOR_TRAEFIK_OPEN_URL               http://localhost:34373

# deSEC API token for DNS-01 ACME challenges (see below). Empty by default.
HARBOR_TRAEFIK_DESEC_TOKEN

# How long (seconds) Traefik waits for the _acme-challenge TXT record to
# propagate before asking Let's Encrypt to verify it.
HARBOR_TRAEFIK_DESEC_PROPAGATION_TIMEOUT   180
```

#### TLS via Let's Encrypt (DNS-01 / deSEC)

Every generated `compose.x.traefik.<service>.yml` router ([`.scripts/seed-traefik.ts`](../.scripts/seed-traefik.ts))
carries a `tls.certresolver=letsencrypt` label pointing at the resolver configured in
[`services/traefik/traefik.yml`](../services/traefik/traefik.yml). Each service gets its own
individual certificate, issued the first time that service is actually requested over HTTPS —
Traefik's ACME resolvers are on-demand, so bringing `traefik` up alone with no fronted service
running produces no ACME activity at all.

> [!IMPORTANT]
> A router's `tls=true` alone does **not** activate ACME — verified empirically against a live
> Traefik v3 instance; it silently just serves Traefik's self-signed default cert instead. Every
> router needs its own explicit `traefik.http.routers.<name>.tls.certresolver=letsencrypt` label,
> which is why the seed script sets one on every generated file. If you ever hand-write a router
> (a custom compose override, a manually-added label) instead of using the generated cross-files,
> it needs that label too or you'll get no cert with zero log output explaining why.

**Prerequisites:**
- `HARBOR_TRAEFIK_DOMAIN` must be a real domain (or `dedyn.io` subdomain) whose DNS is served by
  deSEC — the default `lan` value only works for LAN-only self-signed setups, DNS-01 needs a
  publicly resolvable zone.
- A deSEC API token (deSEC dashboard → Tokens).

**Setup:**

```bash
harbor config set traefik.domain yourdomain.example
harbor config set traefik.desec_token <token>
harbor down traefik && harbor up traefik
```

The resolver itself (`certificatesResolvers.letsencrypt.acme`) is plain YAML in
`services/traefik/traefik.yml` — none of it needs to vary per-user with one-cert-per-service, so
it stays a normal file instead of an environment-variable block. `DESEC_TOKEN` and
`DESEC_PROPAGATION_TIMEOUT` are the only exceptions — they're set via `environment:` in
`services/compose.traefik.yml` because lego (the ACME library Traefik uses) reads DNS-provider
credentials exclusively from the process environment; there's no YAML config field for them at
all, regardless of how the rest of static config is delivered.

If you want ACME expiry notices sent somewhere other than the placeholder address, edit the
`email:` field in `services/traefik/traefik.yml` directly — it can't be templated with a Harbor
config var, since this file is bind-mounted raw with no env-substitution step.

**`acme.json` permissions are handled automatically.** Traefik refuses to use it for cert storage
unless it's exactly `0600`, but git can't preserve that mode on checkout (it only tracks an
executable bit), and Docker auto-creates a missing bind-mount *file* target as an empty
*directory* instead — both of which leave a fresh clone broken. Every `harbor` invocation
guarantees the host-side file exists (`harbor.sh`, before any compose call runs), and a
`traefik-init` sidecar chmods it to `0600` before the main container starts — no manual setup
step needed.

**Verifying it worked:**

```bash
# ACME only triggers once a real router is registered that references the
# resolver. Bring up any one traefik-fronted service to trigger a real order:
harbor up traefik marinara   # or any other service with a traefik cross-file

docker logs harbor.traefik
```

Look for the `letsencrypt` resolver initializing and a successful ACME order for that service's
own hostname; on failure, lego logs the exact deSEC/DNS-01 error (invalid token, propagation
timeout, etc.). `services/traefik/acme.json` (gitignored — it holds private key material once
populated) should grow from 0 bytes to a real certificate bundle.
