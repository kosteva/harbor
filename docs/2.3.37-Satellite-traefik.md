### [traefik](https://github.com/traefik/traefik)

> Handle: `traefik`<br/>
> URL: [http://localhost:34373](http://localhost:34373)

![traefik screenshot](harbor-traefik.png)

Traefik (pronounced traffic) is a modern HTTP reverse proxy and load balancer that makes deploying microservices easy.

#### Starting

```bash
harbor up traefik
```

- Harbor creates relevant traefik service files [via a seed script](../.scripts/seed-traefik.ts).

#### Configuration

If Harbor's [default traefik config](../services/traefik/traefik.yml) doesn't suit your needs the
expected way to configure traefik is to provide a custom configuration file.

```bash
# Path should either be global or relative to $(harbor home)
harbor config set traefik.config /path/to/your/traefik.yml
```

Apart from that, the following options can be set via [`harbor config`](./3.-Harbor-CLI-Reference.md#harbor-config):

```bash
HARBOR_TRAEFIK_HOST_PORT              80
HARBOR_TRAEFIK_HTTPS_HOST_PORT        443
HARBOR_TRAEFIK_METRICS_HOST_PORT      34372
HARBOR_TRAEFIK_DASHBOARD_HOST_PORT    34373

# Traefik version to use (docker image tag)
HARBOR_TRAEFIK_VERSION                v3
# Docker image to use for traefik
# the default one is from traefik's official docker hub
HARBOR_TRAEFIK_IMAGE                  traefik

# Default Harbor setup will pre-configure services
# on the <service-handle>.${HARBOR_TRAEFIK_DOMAIN} domain
# example: ollama -> ollama.lan
HARBOR_TRAEFIK_DOMAIN                 lan

# Path should either be global or relative to $(harbor home)
HARBOR_TRAEFIK_CONFIG                 ./services/traefik/traefik.yml

# URL that'll open when you call "harbor open traefik"
HARBOR_TRAEFIK_OPEN_URL               http://localhost:34373
```

#### TLS via a provided certificate

Every generated `compose.x.traefik.<service>.yml` router ([`.scripts/seed-traefik.ts`](../.scripts/seed-traefik.ts))
carries `tls=true` with no certresolver, so it just uses whatever default certificate Traefik has
configured. Harbor points that default at a wildcard certificate you provide, via a dynamic
config file ([`services/traefik/dynamic.yml`](../services/traefik/dynamic.yml)) loaded alongside
the static config.

**Setup:**

1. Obtain (or generate) a wildcard certificate covering `*.${HARBOR_TRAEFIK_DOMAIN}` — `*.lan` by
   default. A self-signed CA works fine for LAN use; trust that CA on any client machine that
   should see a green padlock instead of a browser warning.
2. Drop the cert and key into `services/traefik/certs/` (gitignored) as `wildcard.crt` and
   `wildcard.key`.
3. `harbor down traefik && harbor up traefik`.

No config vars, no external DNS, no per-service certificates — every fronted service reuses the
same wildcard.

**Verifying it worked:**

```bash
harbor up traefik webui   # or any other service with a traefik cross-file

docker logs harbor.traefik
curl -vk https://webui.${HARBOR_TRAEFIK_DOMAIN}
```

The `curl` output's `subject:`/`issuer:` lines should show your wildcard cert, not Traefik's
built-in `TRAEFIK DEFAULT CERT` — that fallback means the file provider isn't loading
`dynamic.yml` or the cert files aren't present at `services/traefik/certs/`.
