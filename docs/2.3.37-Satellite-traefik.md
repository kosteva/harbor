### [traefik](https://github.com/traefik/traefik)

> Handle: `traefik`<br/>
> URL: [http://localhost:34373](http://localhost:34373)

![traefik screenshot](harbor-traefik.png)

Traefik (pronounced traffic) is a modern HTTP reverse proxy and load balancer that makes deploying microservices easy.

#### Starting

```bash
harbor up traefik
```

- Harbor creates relevant traefik service files [via a seed script](../.scripts/seed-traefik.ts).

#### Configuration

Traefik's entire static configuration is delivered via environment variables in
`services/compose.traefik.yml` — nothing is mounted at `/etc/traefik/traefik.yml`. (Traefik
stops accepting new top-level static-config sections from env vars the instant any file is
mounted there, regardless of content, so a config file and env-driven config are mutually
exclusive — see the DNS-01 section below for how this was discovered.)
[`services/traefik/traefik.yml`](../services/traefik/traefik.yml) is kept in the repo as a
readable reference for what those env vars express, but it's not read by the container.

The following options can be set via [`harbor config`](./3.-Harbor-CLI-Reference.md#harbor-config):

```bash
HARBOR_TRAEFIK_HOST_PORT              80
HARBOR_TRAEFIK_HTTPS_HOST_PORT        443
HARBOR_TRAEFIK_METRICS_HOST_PORT      34372
HARBOR_TRAEFIK_DASHBOARD_HOST_PORT    34373

# Traefik version to use (docker image tag)
HARBOR_TRAEFIK_VERSION                v3
# Docker image to use for traefik
# the default one is from traefik's official docker hub
HARBOR_TRAEFIK_IMAGE                  traefik

HARBOR_TRAEFIK_CERT_EMAIL             harbor@harbor.sh

# Default Harbor setup will pre-configure services
# on the <service-handle>.${HARBOR_TRAEFIK_DOMAIN} domain
# example: ollama -> ollama.lan
HARBOR_TRAEFIK_DOMAIN                 lan

# URL that'll open when you call "harbor open traefik"
HARBOR_TRAEFIK_OPEN_URL               http://localhost:34373

# deSEC API token for DNS-01 ACME challenges (see below). Empty by default.
HARBOR_TRAEFIK_DESEC_TOKEN

# How long (seconds) Traefik waits for the _acme-challenge TXT record to
# propagate before asking Let's Encrypt to verify it.
HARBOR_TRAEFIK_DESEC_PROPAGATION_TIMEOUT   180
```

#### TLS via Let's Encrypt (DNS-01 / deSEC)

Every generated `compose.x.traefik.<service>.yml` router ([`.scripts/seed-traefik.ts`](../.scripts/seed-traefik.ts))
carries a `tls.certresolver=letsencrypt` label pointing at the resolver configured below. Wiring
up DNS-01 with [deSEC](https://desec.io/) as the provider gets a real, browser-trusted
**wildcard** certificate covering `*.${HARBOR_TRAEFIK_DOMAIN}` and the bare domain, issued once
by whichever router's traffic requests it first and reused by every other service under that
domain — no separate ACME request per service, no port 80 exposure requirement (unlike HTTP-01).

> [!IMPORTANT]
> A router's `tls=true` alone does **not** inherit a default `certResolver` set at the entrypoint
> level, even though that seems like the obvious design — verified empirically against a live
> Traefik v3 instance. Every router needs its own explicit `tls.certresolver` label, which is why
> the seed script sets one on every generated file. If you ever hand-write a router (a custom
> compose override, a manually-added label, etc.) instead of using the generated cross-files, it
> needs that label too or ACME will never activate for it — silently, with zero log output.

**Prerequisites:**
- `HARBOR_TRAEFIK_DOMAIN` must be a real domain (or `dedyn.io` subdomain) whose DNS is served by
  deSEC — the default `lan` value only works for LAN-only self-signed setups, DNS-01 needs a
  publicly resolvable zone.
- A deSEC API token (deSEC dashboard → Tokens).

**Setup:**

```bash
harbor config set traefik.domain yourdomain.example
harbor config set traefik.desec_token <token>
harbor config set traefik.cert_email you@example.com   # Let's Encrypt notifications
harbor down traefik && harbor up traefik
```

**All of this is environment variables in `services/compose.traefik.yml` — nothing is mounted at
`/etc/traefik/traefik.yml`.** An earlier version of this split the config between a static file
(for values that never vary, like the DNS provider name) and env vars (for per-user values like
the domain). That doesn't work: verified empirically that once *any* file is mounted at
`/etc/traefik/traefik.yml`, Traefik stops accepting brand-new top-level static-config sections
from environment variables at all — not a per-field merge, a hard cutoff. Since the wildcard
domain (`entryPoints.websecure.http.tls.domains`) was only ever set via env, it was silently
dropped every time, leaving the resolver fully dormant: no eager domain to request a cert for,
and no live traffic yet hitting a real `https://<service>.<domain>` route to trigger Traefik's
otherwise-lazy on-demand ACME behavior — hence zero log output, not an error. Moving everything
(`api`, `providers.docker`, all `entryPoints`, `certificatesResolvers`) to env vars and dropping
the file mount fixes this; `DESEC_TOKEN`/`DESEC_PROPAGATION_TIMEOUT` were always env-only anyway
(lego reads DNS-provider credentials directly from the process environment, no Traefik config
field for them exists).

**`acme.json` permissions are handled automatically.** Traefik refuses to use it for cert storage
unless it's exactly `0600`, but git can't preserve that mode on checkout (it only tracks an
executable bit), and Docker auto-creates a missing bind-mount *file* target as an empty
*directory* instead — both of which leave a fresh clone broken. Every `harbor` invocation
guarantees the host-side file exists (`harbor.sh`, before any compose call runs), and a
`traefik-init` sidecar chmods it to `0600` before the main container starts — no manual setup
step needed.

**Verifying it worked:**

```bash
# Confirm the wildcard domain actually landed in Traefik's parsed config —
# if `domains` is missing here, ACME will never activate for anything.
curl -s http://localhost:34373/api/entrypoints/websecure

# ACME only triggers once a real router is registered that references the
# resolver — bringing traefik up alone, with no fronted service, produces no
# ACME activity at all (this is expected, not a bug: on-demand resolvers
# only fire for a router that actually needs a cert). Bring up any one
# traefik-fronted service to trigger a real order:
harbor up traefik marinara   # or any other service with a traefik cross-file

docker logs harbor.traefik
```

Look for the `letsencrypt` resolver initializing and a successful ACME order; on failure, lego
logs the exact deSEC/DNS-01 error (invalid token, propagation timeout, etc.).
`services/traefik/acme.json` (gitignored — it holds private key material once populated) should
grow from 0 bytes to a real certificate bundle.
